Estimate → Sage X3

Upload an estimate. Get the X3 product, BOM and route import files and the write-up, checked against Sage X3's own product list, saved in K:\Operations\Reporting\SageEstimates. A READY run can be loaded into Sage X3 (test company, after a check).
User guide - how to use this page
💬 Ask the guide - e.g. "what does NOT READY mean?", "how do I load it into X3?", "where are the files saved?"

Answers come from this guide only - Claude doesn't see the estimate or the X3 files. Please don't type customer or supplier details in the question.

What it does

Turns a saved estimate into the three Sage X3 import files - the product (ZSDIITM), its bill of materials (YA00408BOM) and its route (ZSDIROU2) - and a write-up workbook that shows every line of the estimate, where it lands in X3 and how each quantity and run time is worked out. Every line is checked against Sage X3's own product list and work centres first. A READY estimate can then be loaded into Sage X3 from this page (step 7) - into the test environments only: We are SDI (UAT) or SDI Mig, never live.

Steps

  1. Choose the Sage X3 environment (top right): We are SDI (UAT) - where you test - or SDI Mig (test). The estimate is checked against that environment's product list, its saved folder is tagged _UAT_ or _MIG_, and "Load into Sage X3" puts it back into that same environment. The choice is shared with Live Orders.
  2. Add the estimates: drop one or several in the box (or click to choose them) - the .xls or .xlsx exactly as the estimator saved them. Both the estimators' template and Dave's IMPORT layout are read. They go on a list; ✕ takes one off.
  3. Options (leave them unless you know otherwise): Category if the part is new FGML (or FGSL); Sheet steel material CR4 unless the estimate says ZINTEC or Galvanised; Part code only to override the estimate's own code (e.g. a test part); IMPORT layout only where the revision goes.
  4. Press ① Pre-check. Each estimate is read and checked against Sage X3 - a few seconds each - and the list shows READY or NOT READY, the part code, and how many BOM lines and route operations it makes. Press 👁 View on any of them to check it here: the Product file, BOM file and Route file tabs show exactly what goes into Sage X3, Estimate → X3 shows where each line came from in the estimate, and Checks lists anything to fix.
  5. Press ② Publish to Sage X3 to load every READY estimate on the list, and type PUBLISH to confirm. Or skip the review: ⚡ Check and publish in one go pre-checks the list and publishes the READY ones straight away. Either way a NOT READY estimate is never published - it's missing something Sage X3 would refuse - so fix it and add it again. Publishing only goes into the test environments, only creates what X3 hasn't got, and never changes or deletes anything.
  6. READY TO LOAD (green): every line checked. NOT READY (red): the Checks tab lists each STOP with the estimate cell to fix - fix it in the estimate, save, and run it again. WARN = have a look; INFO = for information.
  7. Where the files go: a READY run is saved in K:\Operations\Reporting\SageEstimates, in its own folder named by part, date and time (e.g. XX-0000001_2026-11-20_2015): the three .txt load files and the write-up. The page shows the folder, with Copy path. You can also download them here. A NOT READY run isn't saved there.
  8. One at a time instead: 👁 View an estimate, then use the Load into Sage X3 box under it:
    1. Check against Sage X3 reads X3 (nothing is written) and lists what would be created: the product, the BOM, the route. Anything X3 already has shows as ALREADY IN X3 - left as it is: this page only creates, it never changes or deletes an existing part, BOM or route.
    2. Load into Sage X3: type the part code to confirm. It creates them in order - product, BOM, route - and stops at the first thing X3 refuses, with X3's message. The result is kept with the run (and in the saved folder) and shows as IN X3 in the lists.
    3. Then open the part in X3 and compare its BOM and route with the write-up.
    By hand instead: Usage → Imports, in the environment the folder is tagged with (UAT or MIG), product, then BOM, then route, from the saved folder (X3 rejects the product line if the part exists - expected).

📂 Saved estimates - earlier files

The 📂 Saved estimates button (top right) lists every folder in K:\Operations\Reporting\SageEstimates, newest first (or oldest, or by part), with a search. For each: Open shows it on this page again (with the X3 load), Files lists its files with Preview (look inside without Excel) and Download, and Copy path. After every READY run the page also checks the folder and confirms the files are there.

Common STOPs and what to do

  • "… not a product in X3" - the component must exist in X3 before the BOM loads: use the right code, or have the product created first.
  • "work centre … is not an X3 work centre" - the estimate's department has no X3 work centre (e.g. OVEN): it needs mapping before that operation can load.
  • "no link quantity" / "no part code" - a quantity or code is missing on that estimate line.
  • Sheet steel "no X3 sheet" - no X3 sheet of that size, gauge and material: check the size, gauge or the material option.

Not carried into X3 (shown in the write-up): scrap %, and the estimate's costs - the standard-cost load is still to come. Every run is kept under Earlier runs - click one to see it again; READY ones are also in 📂 Saved estimates. Questions: James Gray.
