SOLIDWORKS PDM: questions for the install

What SDI Intelligence needs to know about PDM before the software side is built on it: reaching the database, the vault and its local cache, versions and revisions, and how our tools follow a file. Take it to the reseller and Ian, and write the answers in the boxes.

These answers are also the evidence for the end-of-October go/no-go between PDM Standard and the SDI Design Vault. That decision turns on whether the estimating tools, Drawing Search, Sage, QC and the AI can reach the design data through PDM.

Prepared by James Gray · SDI Intelligence · 30 September 2026 · for the reseller, Ian, Jack and Yogesh

First meeting: the six to settle

  1. PDM Standard or Professional, and what an outside program may do with it, in writing.
  2. A read-only database login for SDI Intelligence.
  3. A PDM licence and a local vault view for the runner account on the new server.
  4. Which workflow state counts as "released" for estimating.
  5. The list of data-card variables.
  6. The migration plan and date for the K: drive.

1 · Product and version

Standard and Professional differ most in what other software can reach, and everything below depends on which one this is.

☐
Is it PDM Standard or PDM Professional, and which year's release?Ask: reseller
☐
What can an outside program do with it? Read file properties, get a file and its references, list versions, be told when a file is checked in.Ask for this in writing for the exact product. PDM Standard's automation interface is more limited than Professional's.Ask: reseller
☐
Is there a route from Standard to Professional later, and what would it cost?Ask: reseller

2 · The database

Search and reporting tools usually read the PDM database directly. That is common practice, but Dassault does not support it and the table layout can change between versions.

☐
Which SQL Server edition and version, on which machine?PDM Standard runs on SQL Server Express, which caps a database at 10 GB.Ask: reseller / Jack
☐
What are the vault and database names?Ask: reseller
☐
Can SDI Intelligence have a read-only SQL login?Ask: reseller / Jack
☐
Will we be told before an upgrade that changes the database layout?Ask: reseller
☐
How large is the database expected to grow, and what happens near the 10 GB cap?Ask: reseller

3 · Where the files live: vault, archive and local cache

The vault keeps files in an archive under internal numbered names. People and programs work on copies in a local vault view. Our tools must never read or write the archive directly.

☐
Where do the archive server and its storage sit?Ask: reseller / Jack
☐

☐
How big does the local cache get, where does it live, and how is it cleared?Ask: reseller

4 · Versions and revisions

Every check-in makes a new version; a revision (A, B …) is a label the workflow sets. Our quotes name a revision, so estimating needs to know which one it is reading.

☐

☐

☐

7 · Knowing when something changes

Drawing Search and the estimating tools need to stay current without re-reading every file.

☐

8 · File identity and fingerprints

Drawing Search tracks files by path and a file fingerprint (hash) today. In a vault the lasting identity is PDM's own document ID and version, and the path depends on each person's local view.

☐

☐
Can the document ID and version be read with each file? Our indexes should key on these, not on the path.Ask: reseller
☐
