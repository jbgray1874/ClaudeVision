◆ SDI Estimating Intelligence — the application

An estimator can now run a job without a command line Developer Testing

Owner · James Gray

A new page, SDI Estimating Intelligence, has been built into the SDI Intelligence portal — not as a separate site, but as another item on the existing navigation, so there is one place to go. It was proven end to end on Wednesday 5 August on a live Boots enquiry.

  • Enter units, client and drawing number — the run button stays disabled until all three are present, and stays disabled for the whole of a run so a job cannot be started twice.
  • Browse the CAD vault and the estimating shares from the page — \\sdi-dc01\CAD included. Add a job folder, or add drawing files, including every file in a folder in one click.
  • Deliverables are filed automatically to \\sdi-dc01\...\AI Estimating\AISheets\<Client>\<Drawing>, created if it does not exist. Each run goes into its own dated sub-folder, so re-running a drawing can never overwrite an earlier estimate.
  • Six files per run — the costed workbook, the client quote, the decision report, the summary JSON, the AI extract and the complete run console. The console is filed with the estimate, so a number on the share can always be traced back to how it was produced.
  • Completed estimates are browsable and readable from the page — reports open in a tab, workbooks download to Excel.
What this changes. Until this week, running an estimate meant a developer at a terminal. It now takes three fields and a button, and files its own output where estimating already looks for it. That is the difference between a capability and a workflow.
It cannot go to the server yet, and it needs a period of testing first. Two reasons, both real. (1) The service currently has no user authentication — anyone who can reach the port can browse the CAD vault with the service's rights. Windows Authentication and AD group control are scheduled before launch. (2) There is no server it can run on (see Infrastructure below). It stays in developer testing on a named machine until both are closed.

▣ Infrastructure — the estate cannot host this

SDI-APP01 is not fit to run anything AI Spend Required

Owner · James Gray  ·  IT / Infrastructure

An assessment was carried out this week against the estate documented in July. The conclusion is unambiguous: there is currently no server that can host SDI Estimating Intelligence.

HostAlready carriesAssessment
SDI-APP01 · 10.0.0.5
DL380 Gen11 · 32 GB · Xeon 6526Y		 SOLIDWORKS PDM (Archive, ConisioDb, PDM SQL, SolidNetWork licence) · TRUMPF (TRUMPFSQL2 + brokers) · SDI Intelligence portal :8071 Not fit. Two SQL Server instances on 32 GB before anything is added. The estimating engine drives SOLIDWORKS and Excel through COM, which needs a licensed interactive desktop session — not a Windows service — and a SOLIDWORKS session on a real assembly is several gigabytes. A hung Excel on that box is a PDM outage, not a failed estimate.
Second DL380 Gen11
Domain controller		 AD / DC role Not suitable. A domain controller must not run SOLIDWORKS, Office automation or an interactive user session.
5 × VMware VMs
Server 2019 · Xeon 6242		 ERP, data and remote-access tiers Possible interim. Viable as the interim launch host if a VM can be given a SOLIDWORKS seat, Office and an interactive session. Capacity being confirmed.

All AI work currently runs on three developer laptops. That is the largest operational risk in the programme after validation throughput — the production capability, its output history and its learning corpus sit on machines that are not backed up as servers, not resilient and not available to anyone else.

Sequencing decision. Lead times have not yet been established, but between resourcing, cost approval and hardware availability it is unlikely that a permanent server can be ready by 7 September. Rather than couple the launch to procurement, the plan launches on an interim host and moves to the permanent AI host once it is available. This protects the date without shipping onto a platform that puts PDM at risk.

Required purchases

  • Dedicated AI / estimating host, kept separate from the PDM estate.
  • Memory uplift for SDI-APP01 — 32 GB is under-provisioned for the PDM and TRUMPF estate it already runs, irrespective of this programme.
  • One SOLIDWORKS seat and one Office licence for the runner account. Both are necessary — the engine automates SOLIDWORKS and Excel directly and there is no licence-free substitute.
  • Domain service account SDI\svc-sdiintel — read on the CAD share, modify on AISheets, and Allow log on locally. Requested from IT on 5 August.

£ Licensing review — SolidWorks APIs

What the engine actually requires Confirmed

Owner · James Gray

The question was raised this week of whether the server needs a separate SolidWorks API licence. A review of what the estimating engine binds to gives a clear answer, and it has a bearing on the hardware specification.

APILicensingUsed by Estimating?Requires
SOLIDWORKS API (COM)
SldWorks.Application		 Included with any SOLIDWORKS seat. No separate key, no additional cost. Yes — this is the one A SOLIDWORKS seat, installed, with an interactive session
Document Manager API
SwDocumentMgr		 Key-licensed — £1,000 per quarter. No — serves the Design Automation workstream A licence key only. No SOLIDWORKS install, no session
Conclusion — no additional API licence is needed for Estimating. The engine uses the COM API, which is included with a SOLIDWORKS seat SDI already licenses through SolidNetWork. There is no separate per-quarter API charge to add for this programme.
What this does mean is that the seat itself is not optional. The COM API is the reason the estimating host needs a SOLIDWORKS seat, an Office licence and an interactive session — it drives SOLIDWORKS and Excel directly, and cannot run headless. The Document Manager API is a different tool serving a different purpose in the Design Automation workstream; it is not a substitute for the COM API and cannot carry estimating. The seat and the Office licence must be carried in the hardware specification.

◈ Model Engine — accuracy work this week

Costing correctness and evidence integrity Landed

Owner · James Gray
  • Order quantity now honoured end to end. Batch economics, setup recovery and the workbook order quantity all move together, and an invariant check confirms the quantity costed is the quantity ordered. Previously a job could be costed at one quantity and rendered at another.
  • Assembly hierarchy applied to costing. SolidWorks native models now supply the parent/child structure, so an operation charged on a parent is not charged again on its child. A new invariant reports any case where it happens.
  • Thickness now read from the arbitrated source rather than re-derived — a 28 mm MFC panel was previously reported as 16 mm in the decision report while being costed correctly.
  • Deliverables can no longer be silently lost. The filing step now identifies a run's output by what the run actually wrote, rather than by guessing at filenames — which had two different conventions.
  • Open gap — DWG files are not read. The ODA File Converter is not deployed, so a later revision sitting in a pack as a DWG is invisible to the engine. Observed live this week on the Boots pack: a Rev C DWG in a Rev B folder, unread. Free download; scheduled for deployment.
  • Open gap — an unlabelled price origin still reads as firm. In the release-candidate scope before freeze.
