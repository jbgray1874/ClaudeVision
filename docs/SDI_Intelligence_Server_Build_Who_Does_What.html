SDI Intelligence server: who does what

Jack builds the machine and hands over a Windows 11 virtual machine that behaves like a new laptop on the network, with the graphics card inside it. James takes it from there, exactly as he would set up a laptop. The handover checks in the middle are the line between the two.

Infrastructure: the host and the VM

Everything below the applications: hardware, operating systems, network, accounts, backup. In build order.

The host (Windows Server 2025)

  1. BIOS: latest firmware; enable virtualisation (SVM) and IOMMU, which the GPU pass-through needs.
  2. Storage: set up the two NVMe drives (mirror or split OS / VMs — Jack's call) and install Windows Server 2025 with current drivers.
  3. Network and domain: fixed IP, DNS name, join the domain.
  4. Hyper-V: add the Hyper-V role.
  5. Service account for the SDI Intelligence portal service, with read/write to the estimating shares by UNC path (\\server\share, not K:).
  6. Firewall: allow the portal port (8071) from the office network and from the VM.

The VM (Windows 11)

  1. Create it as Generation 2 with Secure Boot and a virtual TPM (Windows 11 requires both).
  2. Fixed resources: 12 virtual CPUs, 48 GB memory with Dynamic Memory off, a 300 GB+ virtual disk on NVMe.
  3. Pass the RTX 4000 through to the VM (Discrete Device Assignment), then install NVIDIA's RTX workstation driver inside the VM. GPU partitioning is not needed.
  4. Windows 11 Pro, fixed IP and DNS name, joined to the domain, fully updated.
  5. Runner account: a dedicated domain user that logs on automatically at boot; read/write to the estimating shares by UNC path.
  6. Power and lock policy: no sleep, no screen lock, no screensaver on the VM — SOLIDWORKS and Excel need a live desktop session.
  7. Admin access for James on both machines: Remote Desktop, and the host's admin share (the laptop's push-to-server.ps1 copies through it).

Running it

  1. Backups: host and VM, with one restore tested before go-live.
  2. Windows Update: restarts scheduled out of hours, host and VM on different nights.
  3. Antivirus: apply the exclusions James supplies (SOLIDWORKS temp and the output folders).
  4. Power: on the UPS, and set to start again after a power cut, with the VM starting automatically.

Handover checks

Jack confirms these, then the machine is James's:

  • In the VM's Device Manager the graphics card shows as NVIDIA RTX 4000 Ada with the NVIDIA driver, not "Microsoft Basic Display".
  • After a full restart of the host, the VM starts and logs in as the runner account with nobody touching it.
  • Signed in as the runner account, the VM can open and save a file in the estimating folders by UNC path.
  • From the VM, the host answers on port 8071 (once James's service is running, this is just a browser test).
  • James can Remote Desktop into both, as an administrator.
James

Applications: the laptop premise

Everything that makes it an SDI Intelligence machine, installed the same way as on the laptop.

On the VM (runs the estimates)

  1. SOLIDWORKS: install and activate (see licensing below), open one model to confirm the graphics card is in use.
  2. Office / Excel: install and activate; open one estimate book.
  3. PDM / Design Vault client, if models come from the vault.
  4. Python and Git, clone the repository, create the engine's .venv.
  5. The .env file, written by hand for this machine — never copied from the laptop.
  6. The runner: scheduled task at logon (restart-runner.ps1) pointing at the host's service.
  7. Hand Jack the antivirus exclusion paths.

On the host (runs the portal)

  1. Python and the service's own .venv, the backend files, and the host's own .env.
  2. Install and start the SDIIntelligence service; check the portal loads from a desk.

Proving it

  1. Run one known job (12645 or 12173) on the VM and compare the book and the run time with the laptop's.
  2. Restart the host and confirm the portal and the runner both come back without anyone logging in.

Agree together before the build week

Rule of thumb: if it would be the same on any Windows machine, it's Jack's. If it only exists because this is SDI Intelligence, it's James's.
