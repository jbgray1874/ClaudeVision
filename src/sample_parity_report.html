6  Design recommendations — for consistent, reliable estimating

These changes to how drawings are produced would let the engine read the drawings rather than cope with them — reducing variation job-to-job and making every future estimate more reliable.

1
Standardise part-number format. One consistent scheme (e.g. JOB-ASSY-NNL) so fabricated parts, sub-assemblies and bought-ins are distinguishable at a glance. Avoid section labels and un-numbered details becoming "parts".
2
State material in the title block of every detail — per part. Don't rely on a single assembly-level material for a multi-material product. Each detail should carry its own MATERIAL: field so nothing inherits the wrong default.
3
Export clean flat-pattern DXFs. No dimension/annotation/note layers in the flat-pattern DXF — geometry only. This single change removes the largest source of mis-read part sizes.
4
No spaces in filenames. This pack has 1448 - GA Upper Leg Assembly_revA .PDF — the space complicates matching. Prefer 1448_-_GA_Upper_Leg_Assembly_revA.PDF. Consistent naming ties each DXF unambiguously to its part.
5
Consistent BOM table layout. Same columns, same order, same identifiers on every GA page — and clearly distinguish printed/graphic/display-board and bought-in items from fabricated parts.
6
Consistent dimension conventions. State overall size on every detail so the engine never has to infer it, and keep dimension text readable even where geometry is complex.
7
Consistent data mappings across drawings. The same field should mean the same thing on every drawing — material, finish, thickness, quantity in fixed places — so the engine can rely on structure instead of guessing per job.
The prize: with consistent drawings, the engine moves from coping with variation to reliably reading a known structure — cleaner BOMs, positively-identified manufacturing routes mapped to shop-floor machines, and estimates that need less manual correction each time.
